一条 64 位密文，如何让车辆进场记录整笔回滚

发表于 2026-11-02 分类于 工程实践

车辆平台有进场记录，本地页面却缺数据。最后定位到的原因不是 MQ 没推送，而是车辆档案里的 64 位手机号密文被原样复制进 VARCHAR(11) 字段；一次字段超长异常，让接收流水、在场车辆和通行记录一起回滚。

🎧 文章导读

页面少数据，先确认页面查的是谁

这次页面查询的是本地车辆通行表，不是实时查询上游平台。接收链路如下：


图 1：上游有记录只证明上游事实，本地页面还依赖消费、服务调用和事务提交。

因此，“上游有、本地没有”只是排查起点。中间任何一步失败，都可能造成页面缺数。

时间字段也要先分清：通行时间来自上游消息时间戳，本地创建时间是保存时间。两者语义不同；设备、上游、应用服务器和截图电脑的时钟未对齐前，不能直接拿差值判断传输延迟，更不能把页面看到的最新时间当作数据库最大时间。

重复推送会淹没真正有用的样本

接收流水里，同一源 ID 大约每几分钟重复出现一次。最初直接取最近 30 行，结果几乎全是重复数据。改为按源 ID、方向、车牌和事件时间分组后，才有可用的对照样本。

这里还发现了另一类独立问题：部分出场消息因为找不到对应进场记录而被跳过。它能解释某些“没有出场业务记录”的样本，却解释不了本次重点追查的进场缺失，所以没有被强行合并成同一个根因，也没有在这次修复中顺手修改。

排查日志时还有两个实用细节：

  • 原始消息带有大段 Base64 图片，先移除图片，再看源 ID、车牌和时间，否则关键字段很容易被淹没。
  • 正常消息正文日志受开关控制，固定错误关键词没有命中，不等于消息没到达，也不等于接收成功。

真正推进定位的是一条完整的证据链：缺失样本已经到达接入服务，并发起对通行服务的调用；随后出现 Feign 500。

500 不是根因，堆栈里的字段才是

接收方法带有事务，异常时会回滚。由此可以解释一个容易误判的现象：为什么连“接收流水”也查不到？因为流水不是在一个已经独立提交的安全岛上，后续写入失败时，它也可能一起消失。

通行服务的异常堆栈最终给出了具体位置：

失败发生在“新增在场车辆”，早于最后的车辆通行记录写入。于是同一次接收中的接收流水、在场记录和通行记录都没有留下。

继续交叉核对表结构和代码，冲突变得明确：

数据位置 手机号存储情况
本地车辆档案 VARCHAR(64)，保存 64 位密文
在场车辆联系电话 原为 VARCHAR(11)
车辆通行记录联系电话 原为 VARCHAR(11)

车辆档案写入链路会对手机号加密；接收上游进场消息时，消息本身并没有联系电话字段。接收服务只是把本地档案的密文原样复制到另外两个字段，展示层本来也支持解密后脱敏。

所以正确修复不是截断密文，更不是改回明文，而是统一存储长度。


图 2：字段长度冲突发生在本地写入阶段，500 与记录缺失都是后续表现。

最小修复：两列扩容，同步实体校验

本次迁移只调整两张目标表：

两个实体的 @Length 上限也同步从 11 改为 64。只改数据库而漏掉校验，仍可能在进入 SQL 前被拒绝；只改实体而不改表，则继续触发数据库异常。Mapper 已按字符串读写，不需要额外转换。

这次没有改 MQ 消费方式、接收事务边界、出场关联逻辑或时间处理，也没有改写、截断、解密历史号码。改动范围与已经证实的根因保持一致。

回归验证要覆盖旧结构和边界值

原记录中的 3 项回归测试先基于历史表结构确认 64 位密文会被拒绝，再执行新增迁移，验证两张表都能完整保存密文，同时保留原 11 位号码和空值行为。实体测试覆盖 11 位明文、64 位密文和 65 位拒绝，另检查明文与密文展示时的脱敏结果。

当时 Maven 目标测试结果为 Tests run: 3, Failures: 0, Errors: 0，reactor 构建成功。数据库回归使用的是 H2 MySQL 兼容模式，不是生产 MySQL 迁移后的接收实测。

这项区分很重要：测试证明修复针对已定位的字段冲突有效，但不证明所有历史差异都已消失。

修复完成，不等于历史记录已经恢复

原笔记结束时的状态是源码修复和本地验证完成，生产迁移、服务部署、历史补数仍待执行。上线后至少还要核对：

  1. 两列在目标库均为 VARCHAR(64)，服务包含同步后的实体校验。
  2. 受影响车辆的新消息不再因该字段返回 500，页面可以查询到对应记录。
  3. 从上游或保留的原始消息重推、补回失败记录，并逐条对账；不能假定重复推送会一直存在。
  4. 继续追查未闭环样本、出场缺少对应进场的问题，以及各系统时钟差异。

这次排查最值得复用的方法，是把“平台有数据”拆成消息到达、服务调用、具体写入和事务提交四层证据。根因最终只是一处长度不一致，但只有完整链路才能解释为什么一个字段会带走整笔车辆记录。
